# Adapter feature-parity audit

Date: 2026-10-19. This is an implementation audit, not a claim that an older
adapter's API is a suitable Astro 7 API. It covers every documented option and
runtime behavior found in the five repositories requested for review, plus the
implementation behaviors needed to assess static output, SSR, and ISR.

Only Wyatt supports Astro 7, and its stated peer range is older than the
currently targeted 7.4.0. Nuro, Ido, Zastinian, and Scaliir cannot establish
Astro 7 compatibility. “Implemented” below means the current source and a
named local test prove the behavior. “Unverified” means source suggests it
might work but the repository has no focused local proof. “Gap” is an absent
capability, not a defect by itself.

## Issues that changed the implementation priority

The issue review was read-only and found the following live evidence:

1. [Wyatt #17](https://github.com/wyattjoh/astro-bun-adapter/issues/17) reports non-relocatable production builds. Ours has an integration test that copies the completed build before starting it; retain it whenever manifest or path code changes.
2. [Nuro #2](https://github.com/NuroDev/astro-bun/issues/2) remains open for built 500-page failover. Our running integration fixture now asserts the custom 500 page and no exception-marker leakage.
3. [Nuro #14](https://github.com/NuroDev/astro-bun/issues/14) remains open for Unix-socket client addresses. Do not add proxy-header inference as a workaround; it is a trust-boundary feature.
4. [Scaliir #54](https://github.com/ScaliirDigital/root/issues/54) is open for `Astro.clientAddress`. Ours passes Bun's direct address and tests it for TCP.

The other repository issue trackers either reported no issues (Zastinian), are
disabled (Ido), or had release/platform issues outside runtime behavior. This
does not prove their implementations are bug-free.

The SSE row concerns automatic timeout management, not whether Astro can
produce an event stream. The HTTP/2 row excludes reverse-proxy termination.

Implementation and validation:

- **SSE timeout control:** successful event streams use Bun's per-request
  timeout API. Tests cover quiet periods, explicit limits, opt-out, ordinary
  stream timeouts, cache bypass, and cancellation on client disconnect.
- **Native WebSocket endpoint:** an explicit bundled module supplies an async
  authorization hook and Bun handlers. Tests cover text/binary frames, origin
  checks, denied upgrades, base paths, production preview, and missing handlers.
  Upgrades run outside Astro middleware, so authorization belongs in the hook.
- **Opt-in HTTP/2:** Bun's experimental TCP server option supports cleartext
  prior knowledge and TLS ALPN while retaining HTTP/1.1. Both are exercised

### Multi-process platform caveat

The cluster options in Nuro and Zastinian are not evidence of cross-platform
HTTP load balancing. Nuro forks `Bun.serve()` workers without `reusePort`;
Zastinian enables `reusePort` when clustering. Bun documents native same-port
HTTP load balancing as [Linux-only](https://bun.sh/guides/http/cluster).

Minimal reproductions of these process patterns on macOS with Bun 1.4.3
(2026-10-19) found that, without `reusePort`, the second worker failed with
`EADDRINUSE`. With `reusePort`, both workers listened, but all 100 serial HTTP
requests with `Connection: close` reached a single worker. These were isolated
runtime probes, not end-to-end tests of the competitor packages; Windows was
not tested. The README therefore marks their cluster support with a caveat.
Our same-port supervisor remains Linux-only and is exercised in Linux CI.
Independent instances on separate ports can instead sit behind an external
load balancer on other operating systems.
